# Local-emulator gotchas — what does NOT match real AWS

These apply to any LocalStack-style emulator (Floci, MiniStack, LocalStack). A local pass is a fast check of **wiring and logic** — it is never proof of real-AWS behavior. Each row: what breaks → mitigation.

| Area | What breaks | Mitigation |
|---|---|---|
| **IAM / authorization (NOT enforced)** | Every call is authorized regardless of policies, roles, trust, resource policies, permission boundaries, or SCPs. A missing grant, an over-broad `*`, or a broken assume-role trust never surfaces locally — it returns `AccessDenied` only in real AWS. A green local run is **not** proof of authorization. | Validate policies in a throwaway least-privilege sandbox, plus static analysis (IAM Access Analyzer / policy simulator / cfn-policy-validator in CI). Treat any `ENFORCE_IAM` toggle as an under-enforcing smoke test at best. |
| **Credentials / SigV4** | Any non-empty creds accepted; signatures, token expiry, and MFA are not verified. Expired sessions, wrong secret keys, clock skew, missing session tokens never raise `SignatureDoesNotMatch` / `ExpiredToken` / `InvalidClientTokenId`. | Contract-test the credential / refresh / assume-role paths against real STS. Don't rely on local runs to catch signing or credential-plumbing bugs. |
| **STS / account ID / ARNs** | `get-caller-identity` returns `000000000000` (unless a 12-digit key is set); every ARN is built from that fake account. Real `AKIA…`/`ASIA…` keys fall back silently to the default account, masking wiring bugs. | Resolve the account at runtime from STS; never hardcode it or parse it out of an ARN. Parameterize account in IaC. Verify account-scoped things (cross-account policies, KMS grants) in a real account. |
| **Cross-account & cross-region** | Accounts/regions are a flat namespace in one process. S3 CRR, DynamoDB global tables, cross-account `AssumeRole` trust, RAM shares, region-scoped quotas are not isolated or enforced. Multi-region failover "works" because no real boundary exists. | Exercise every cross-account/cross-region flow in real AWS with the actual accounts/regions. Use local namespacing only for coarse smoke tests. |
| **Service / feature parity & stubs** | Coverage is per-operation and uneven: some services are full, some partial, some mock-only (canned responses, no side effect). An HTTP 200 does **not** mean the trail/metric/analytics/ML work happened. New AWS params lag and may be silently ignored. | Check per-service AND per-operation coverage before depending on it. Assert on observable side effects, not status codes. Do the real assertion for mock-only services in a cloud test. |
| **Ephemeral state** | In-memory by default; wiped on every container restart — buckets, tables, queues, secrets, stacks vanish. Tests that assume data survives a restart break. | Treat every run as ephemeral: seed fixtures via init hooks / IaC at startup; reset between tests (`/_floci/state/reset`, `/_ministack/reset?init=1`). Re-seed rather than trusting an old snapshot. |
| **CloudFormation / CDK / Terraform** | The CFN engine is a reimplementation. Unsupported resource types may be silently ignored; UPDATE/change-set support is limited; some intrinsics/custom resources/drift differ. `cdklocal`/`tflocal` just repoint endpoints. A template that deploys clean locally can fail or build a different graph in AWS. | Validate templates/plans by deploying to a real sandbox account in CI. Make unsupported resources fail loudly. Never treat a local deploy as proof of deployability or drift-freedom. |
| **Networking / VPC / SG / DNS** | VPCs, subnets, route tables, NACLs, security groups, IGW/NAT, VPC endpoints, PrivateLink are metadata-only CRUD — no packet filtering or isolation is enforced. An SG/NACL rule that would block traffic does nothing locally. Route53/DNS behaves differently. | Never validate reachability or network-security posture on the emulator. Test connectivity and SG/NACL rules in a real VPC (Reachability Analyzer, flow logs). Keep local assertions to config shape. |
| **Lambda runtime & timing** | Runs in reused Docker containers, not Firecracker microVMs. Cold-start latency, init timing, memory→CPU proportionality, `/tmp` limits, env reuse, concurrency limits, VPC/ENI attach delays do not match AWS. | Do all performance, timeout, memory-sizing, and concurrency testing on real Lambda. Use AWS base images and pin the runtime for parity. |
| **Eventual consistency & ordering** | Backends are synchronous and immediately consistent: read-after-write, IAM/role propagation, DynamoDB GSI lag, Route53 propagation, SQS/SNS/Kinesis delivery all look instant and in-order. Code that wrongly assumes immediate consistency passes locally and fails intermittently in prod. | Write consistency-tolerant code (retry/backoff, wait-for-condition) and test the delay paths against real AWS. Assert on *eventual*, not immediate, availability. |
| **Pagination** | Many list ops return everything in one page with no realistic `NextToken`/`Marker` and no `MaxResults` enforcement. A handler that never follows the second page passes locally, then drops results at scale. | Use the SDK's built-in paginators (not hand-rolled single reads). Test paginators against real AWS or seed enough items to force paging. |
| **S3 addressing / SSL** | One edge endpoint that must be injected via `endpoint_url`/`--endpoint-url`. S3 needs path-style (`ForcePathStyle=true`) or the special host; virtual-host `bucket.localhost` DNS does not resolve; presigned URLs frequently 403 unless the hostname/endpoint is set right. TLS is self-signed or plain HTTP. | Inject the endpoint via config/env, never hardcode it in app code. Force path-style for S3; verify presigned-URL and TLS behavior against real S3 before shipping. |
| **Cost / quotas / throttling** | No billing, no Service Quotas, no throttling. `ThrottlingException`, `ProvisionedThroughputExceededException`, `LimitExceededException`, `TooManyRequestsException` never fire, so retry/backoff/circuit-breaker and quota-aware batching go untested; a runaway loop looks harmless. | Implement and test retry/backoff and quota handling explicitly. Load-test against real AWS to observe true limits. |
| **KMS / encryption** | Local KMS uses local key material; ciphertext, data keys, and key ARNs are not interchangeable with real KMS, and SSE-KMS / grant enforcement is not truly enforced. | Round-trip encrypt/decrypt and any grant/policy enforcement against real KMS. Never persist locally produced ciphertext expecting real KMS to read it; keep key ARNs configurable. |
| **Deterministic IDs / version lag** | Generated IDs/ARNs/request IDs are often deterministic rather than random; API version lag means new params may be missing or silently ignored. Tests asserting on an exact ID format or a just-released field mismatch real AWS. | Assert on ID shape and round-trip, not literal values. Pin and track the emulator image version; confirm a recent AWS param is actually honored before depending on it. |

## Reserve real AWS (one minimal, authorized, torn-down smoke test) for:

IAM / authorization correctness · credential / SigV4 / refresh paths · cross-account & cross-region behavior · KMS ciphertext interchange · Lambda performance / concurrency / timeout · quotas / throttling · presigned-URL & TLS behavior · final pre-ship sign-off.

Run those through the scoped `six8-scoped` profile (see [`~/.claude/README.md`](../../README.md)), only with explicit per-session authorization, and tear everything down afterward.
